# Agent 自进化

GoGoClaw 可以从反复出现的任务中收集证据并生成工作区技能草稿。功能默认关闭，通过 `evolution` 配置。

## 三种模式

| 模式 | 行为 | 使用场景 |
| --- | --- | --- |
| `observe`（观察） | 记录回合结果和技能使用情况。 | 先积累真实任务案例，暂时不为生成草稿调用模型。 |
| `draft`（草拟） | 记录证据、聚类任务并生成待审阅草稿。 | 评估修改建议，保持当前生效的技能稳定。 |
| `apply`（发布） | 同样生成草稿，并允许在控制台逐份批准发布。 | 将核对过的改进应用到正在使用的工作区。 |

## 学习与草拟

后台记录任务目标和回复节选、回合状态、用到的技能，以及工具名称和执行结果。Heartbeat 回合会跳过。草拟时，系统分批处理符合条件的记录。回合结束代表执行状态，任务是否达成目标由模型另行判定。已知结果会缓存，判断请求失败时保留为未知。没有最终回复的失败回合也能计入成功率。

相似任务达到配置的样本数和成功率后才生成草稿。新增失败会更新已有模式的成功率。证据变化会阻止旧候选发布，满足门槛后生成的新版可替代旧候选，历史版本保留。

`after_turn` 在回合结束后安排草拟，`scheduled` 在配置的本地 `HH:MM` 时间运行，`manual` 等待用户触发。草拟和发布模式均可在 **设置 → 自进化 → 演化草稿** 中点击 **运行草拟**。

## 审阅与恢复

控制台展示学习证据、渲染后的 `SKILL.md` 差异，以及同名全局或内置技能的覆盖提示。草稿一经发布，其指令就可能出现在后续 Agent 的上下文中。请在批准前核对内容。程序会同时检查文档结构和常见的密钥特征。

发布模式下，每份草稿都需要明确批准。批准会绑定本次预览与目标技能的版本，正式写入前会再次检查文件。如果目标发生变化，可以按当前版本重新预览。草拟和发布模式均可拒绝候选草稿。

发布时保留原文件的备份。**回滚版本** 可恢复原文件，或者移除该次发布创建的技能文件。回滚会保护后续修改，自进化关闭后仍可使用。早期版本发布的技能需要手工恢复旧备份。对长期未使用的演化技能，控制台只给出归档建议，由用户决定如何处理。

## 存储与升级

学习记录、模式、草稿和技能档案统一保存在工作区的 `sessions/sessions.db`。首次使用时，GoGoClaw 会在一个事务中导入演化目录里的旧 JSONL 记录、草稿和技能档案。原文件会保留，同一条记录以已有的 SQLite 版本为准。

`state_dir` 用于定位旧数据和 `backups` 子目录，默认是 `<workspace>/state/evolution`。备份工作区时，保留数据库及技能备份目录即可继续回滚。

可配置字段见 [配置指南](../guides/configuration.zh.md#agent-自进化)。
