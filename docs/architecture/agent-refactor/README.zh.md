# Agent 重构

## 本目录的用途

本目录是当前 Agent 重构的工作区域。

这次重构的目的很简单：

在增加更多与 Agent 相关的行为之前，项目需要一个更小、更清晰、更稳定的 Agent 模型。

代码库已经包含有意义的 Agent 行为。它仍然缺少的是围绕这些行为的足够明确且稳定的语义边界。

本次重构首先就是为了解决这一点。

---

## 重构立场

这是一次以维护为主导的整合工作。

它不是并行扩展 Agent 行为的普遍邀请。

在这次重构窗口内，与 Agent 相关的工作应汇聚到当前重构轨道上，而不是分叉出新的语义。

这意味着：

- 先澄清概念，再扩展功能
- 先收紧边界，再增长抽象
- 先整合语义，再增加新行为

---

## 核心规则：只保留最小概念

本次重构遵循一条硬性规则：

**除非绝对必要，否则不要引入新概念**

更明确地说：

- 如果现有概念可以被澄清，就复用它
- 如果现有边界可以变明确，就先这样做
- 如果行为不需要新抽象也能表达，就不要添加
- “未来灵活性”本身不足以成为理由

本次重构的目标不是让模型增长。

目标是减少歧义。

---

## 正在澄清的内容

本次重构目前关注以下问题：

1. 什么是 `Agent`
2. 什么是 `AgentLoop`
3. `AgentLoop` 的生命周期是什么
4. `AgentLoop` 周围的事件面是什么
5. persona / identity 如何组装
6. capability 如何表示
7. 上下文边界和压缩如何工作
8. 子代理协调如何工作

这些是当前的工作边界。

如果需要调整它们，应显式调整，而不是让它们在代码中隐式漂移。

---

## 本目录的状态

这里的文档是工作材料。

它们不是最终版本，也不是不可更改的。

如果当前说明不完整、拆分不正确或范围过宽，就应修订。本目录应随着重构演进，而不是假装第一版草稿已经完成。

---

## 建议的文档拆分

本目录最终可能包含如下说明：

- `agent-overview.md`
  - 什么是 Agent
- `agent-loop.md`
  - AgentLoop 契约、生命周期、事件面
- `persona.md`
  - persona 与 identity 组装
- `capability.md`
  - tools / skills / MCP capability 语义
- `context.md`
  - 上下文作用域、历史、摘要、压缩
- `subagent.md`
  - 子代理协调规则

只有在这些文件有助于澄清当前重构工作时才应添加它们。

本目录不应变成通用架构堆料场。

---

## 本目录不适用于什么

本目录不用于：

- 宽泛的推测性架构
- 当前重构不需要的未来多节点协议设计
- 与 Agent 整合无关的并行功能规划
- 在当前概念尚未澄清前添加新概念

如果某个主题不能直接帮助减少当前 Agent 模型中的歧义，它可能还不应放在这里。

---

## 与实现的关系

实现变更不应持续隐式地重新定义 Agent 语义。

如果某个 PR 更改或依赖 Agent 语义，这些语义应已经存在于这里，或先在一个关联 Issue 中澄清。

本目录的作用是让实现更收敛、更有纪律。

---

## 与 GitHub 跟踪的关系

本次重构的 umbrella issue 应指向这里。

Issue 是协调面。

本目录是仓库本地的工作面。

---

## 总结

本次重构的主要问题不是：

- Agent 还能做什么

主要问题是：

- 当前 Agent 行为可以围绕什么最小稳定模型来组织
